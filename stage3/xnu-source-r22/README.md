# SO-04J source-kernel loader R22

Accepted 2026-10-28: Aliyun Cortex-A72 full gate and one Sony SO-04J native run, 14 consecutive own-PID1 heartbeats, timed return, automatic Android boot, unchanged boot/FOTAKernel hashes.

R21 firmware and return assembly are retained. `KernelContract.h` comes from the new Mach-O, generated by `work/scripts/generate_source_kernel_contract.py`; the entry and root/ADT/args addresses differ from R21. `XnuBoot.h` performs a read-only PAN instruction audit, configures the return data slot, and supplies `/arm-io/timer/p8,timer-intid` (Sony19 / QEMU27). It does not patch kernel instructions.

Kernel: `work/artifacts/stage3-source-kernel-20261028/mach.development.bcm2837`, SHA256 `93919f7e75100f0d39db35c233ca908e918a7ae74f42f6bd253b641908854c53`.

Firmware build uses `build_worker.py` on Aliyun with the existing private GCC9 and EDK2. Source transport/build: `stage_source_r22_sources.py`, `remote_source_r22_stage_part*.py`, `remote_source_r22_build.py`. Run shared-StateDirectory jobs serially. `remote_source_r22_qemu.py` must pass before packaging with `package_source_r22.py` and testing with `test_source_r22_phone.py`. Native acceptance is independently checked by `verify_source_r22_phone.py`.

Captured evidence: `work/captures/stage3-source-r22-20261028/`; packaged temporary image: `work/artifacts/stage3-source-r22-20261028/`. R22 is a frozen accepted run; use a fresh tag and output directory for later modifications.

The phone run uses our 17,024-byte standalone PID1. Apple userland is accepted separately in emulation. Phone root/SystemOS transport and Apple launchd are the next stage.
